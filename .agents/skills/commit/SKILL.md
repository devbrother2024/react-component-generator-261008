# Commit

변경사항의 의도와 범위를 보존하면서, 읽기 쉬운 한국어 커밋 이력을 만듭니다.

## 절차

1. `git status --short`와 `git diff`로 작업 트리 변경을 확인합니다. 이미 스테이징된 변경이 있으면 `git diff --staged`도 확인합니다.
2. 변경을 기능, 버그 수정, 리팩터링, 유지보수 등 서로 독립적으로 되돌릴 수 있는 논리적 단위로 분류합니다. 사용자가 만든 관련 없는 변경은 포함하지 않습니다.
3. 각 단위에 아래 형식의 한국어 메시지를 제안합니다.

   ```text
   feat: 컴포넌트 미리보기 상태를 저장한다
   fix: 빈 프롬프트 생성 요청을 차단한다
   refactor: 생성 요청 흐름을 훅으로 분리한다
   chore: 개발 도구 설정을 정리한다
   ```

   가능한 유형은 `feat`, `fix`, `refactor`, `chore`를 우선 사용합니다. 변경이 없으면 커밋을 제안하지 않습니다.
4. 분류 결과, 포함할 파일, 제안 메시지를 간단히 알린 뒤 승인 대기 없이 진행합니다.
5. 각 단위의 파일만 `git add`로 스테이징하고 `git commit`을 실행합니다. 여러 단위면 독립적으로 되돌릴 수 있는 순서로 각각 커밋합니다.
6. 완료 후 커밋 해시, 메시지, 남은 작업 트리 변경 여부를 보고합니다.

## 안전 경계

- 이 스킬이 트리거된 커밋 요청은 분석·스테이징·커밋의 권한을 포함합니다. 별도 승인 대기는 만들지 않습니다.
- `git reset --hard`, 강제 푸시, 변경 덮어쓰기, 비밀값이 포함된 파일의 스테이징은 이 스킬 범위에 포함하지 않습니다.
- 변경의 의도가 불명확하거나 비밀값이 감지되면 커밋하지 않고 필요한 판단을 사용자에게 요청합니다. 커밋 실패 시 원인과 현재 스테이징 상태를 설명하고 멈춥니다.
