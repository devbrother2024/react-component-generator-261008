# Pull Request 생성

사용자가 GitHub Pull Request 생성을 요청할 때 사용한다. 주 에이전트와 하위 에이전트 모두 사용할 수 있다.

## 생성 전 확인

- 대상 저장소, 현재 브랜치, 베이스 브랜치, 커밋, 작업 트리 상태를 확인한다. 관련 없는 변경이나 미커밋 변경을 포함하지 않는다.
- PR 생성은 외부 변경이다. 사용자가 명시적으로 승인한 경우에만 생성하며, 하위 에이전트는 위임된 승인 범위에서만 동작한다.
- 필요하면 브랜치를 푸시한다. 명시적 지시 없이 강제 푸시하거나 베이스 브랜치를 바꾸지 않는다.

## 템플릿 선택

PR 본문을 만들기 전에 템플릿을 선택한다.

- `origin` GitHub 소유자가 `devbrother2024`인 DevBrothers 저장소에는 [한국어 템플릿](references/pr-body-ko.md)을 사용한다.
- 외부 오픈소스 저장소를 포함한 그 외 모든 저장소에는 [영문 템플릿](references/pr-body-en.md)을 사용한다.
- 사용자가 템플릿을 지정하거나 PR 본문을 제공하면 그 지시를 우선한다.

선택한 템플릿만 읽는다. 모든 플레이스홀더를 저장소별 내용으로 교체하고, 해당하지 않는 섹션은 플레이스홀더를 남기지 말고 제거한다.

## 생성 및 검증

요청된 제목, 베이스 브랜치, 완성된 본문으로 `gh pr create`를 실행한다. 브랜치에 이미 PR이 있으면 중복 생성하지 않고 URL을 보고한다.

생성 후 `gh pr view`로 URL, 베이스 브랜치, 헤드 브랜치, 제목, 본문을 다시 읽어 검증한다. 검증된 URL을 보고한다. 생성 또는 검증에 실패하면 브랜치와 커밋을 보존하고 실패를 보고하며, 사용자가 지시하지 않는 한 대상 변경 후 재시도하지 않는다.

## 하위 에이전트 사용

하위 에이전트도 이 스킬을 호출하고 동일한 템플릿 선택 규칙을 적용한다. 위임받은 작업의 승인 범위를 벗어나 PR을 생성·수정·병합·종료하거나 메시지를 보내서는 안 된다. 검증된 PR URL과 차단 요인을 부모 에이전트에 보고한다.
